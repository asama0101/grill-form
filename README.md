# grill-form

計画や設計を、ブラウザのフォームで答えながら詰めて、最後に SPEC（仕様書）の 1 ファイルにまとめる Claude Code 用のプラグインです（バージョン 1.0.0）。

## 機能

- **ブラウザのフォームで答える**: Claude の質問に、ターミナルではなくフォームで答えます。候補を選ぶ、コメントを書く、保留にする、聞き返す、が使えます。キーボードだけでも操作できます。
- **推奨案つきの質問**: 各質問に、Claude の推奨案と理由が付きます。決めることがなくなるまで、ラウンドを重ねます。
- **資料をツリーから渡す**: 依頼文と参考資料を、作業フォルダのツリーから選べます。PDF・Word・PowerPoint・Excel・Markdown・テキストを、元の場所のまま読みます。
- **SPEC の 1 ファイルだけが残る**: 承認すると、概要・流れ・受入条件・非目標・リスク・決定ログをまとめた Markdown が 1 つできます。別のプラグインや別のセッションに、そのまま渡せます。

## 前提条件

- [Claude Code](https://docs.claude.com/en/docs/claude-code)
- Python 3.8 以上（標準ライブラリだけで動きます）
- [Playwright MCP](https://github.com/microsoft/playwright-mcp): ローカルの HTML を開き、送信を検知するために使います。このプラグインには同梱していないので、導入方法の手順 3 で登録します。
- ブラウザ: Chrome か Edge を推奨します。
- OS: Windows 11 で動作を確認しています。macOS と Linux は、確認していません。

## 導入方法

### 1. マーケットプレイスを追加する

Claude Code で実行します。

```
/plugin marketplace add asama0101/grill-form
```

GitHub を使わず、手元にコピーして入れるときは、次のようにします。

```bash
git clone https://github.com/asama0101/grill-form.git <任意のフォルダ>/grill-form
```

```
/plugin marketplace add <任意のフォルダ>/grill-form
```

### 2. プラグインを入れる

```
/plugin install grill-form@grill-form
```

- 更新は `/plugin` の画面から行います（手元にコピーしたときは、先にそのフォルダで `git pull` します）。反映には Claude Code の再起動が必要です。

### 3. Playwright MCP を登録する

```bash
claude mcp add playwright --scope user -- npx @playwright/mcp@latest --allow-unrestricted-file-access --output-dir "$(python -c 'import tempfile; print(tempfile.gettempdir())')/playwright-mcp"
```

- `--allow-unrestricted-file-access`: `file://` の HTML を開くために必要です。
- `--output-dir`: Playwright MCP の記録の置き場所です。指定しないと作業フォルダに `.playwright-mcp/` ができるので、OS の一時フォルダ配下にします。上のコマンドは、一時フォルダの場所を Python で調べて埋めます。
- ブラウザを指定するときは、`--browser chrome` などを足します。
- すでに `playwright` を登録していると、上書きされません。[困ったとき](#困ったとき)の手順で登録し直してください。

登録したら、Claude Code を再起動します。`claude mcp list` に `playwright` が出れば成功です。

## 使い方

Claude Code で、次のように頼みます。

```
/grill-form:grill-form API の認証方式を詰めたい
```

「grill して」だけでは起動しません。`/grill-form:grill-form` を呼ぶか、「grill-form で〜」「HTML で grilling」と書いたときだけ使われます。

ブラウザにフォームが開きます。「送信」を押すと、Claude が自動で検知して次へ進みます。ターミナルへの入力は要りません。途中でやめるときは、どのフォームでも「中止」を 2 回押します（SPEC は作られません）。

1. **入力フォーム**: 依頼文、参考資料、保存先を渡します。
2. **事前確認**: 目的とゴール、障壁、制約を確認します。Claude が推奨案を埋めるので、確認と修正だけです。
3. **質問ラウンド**: 決めることがなくなるまで、質問のフォームを繰り返します。
4. **最終確認**: SPEC 案が出ます。「承認」で SPEC が保存され、Claude がそのパスを知らせます。「修正あり」を選ぶと、コメントを反映した案がまた出ます。

### 入力フォーム

| 欄 | 内容 |
| --- | --- |
| 依頼文 | 「テキスト」か「ファイル」のどちらかで渡します。テキストは、何を詰めたいか、背景、分かっている制約などの自由記述です。ファイルは、作業フォルダの中から 1 つ選びます |
| 参考資料 | 左のフォルダをクリックすると、右に資料が出ます。チェックで選び、別のフォルダへ移ってもチェックは残ります。Shift を押しながらクリックすると、前にクリックしたファイルから範囲でまとめて選べます |
| 保存先（親フォルダ） | SPEC を置くフォルダを、作業フォルダの中から 1 つ選びます。初めは作業フォルダ自身が選ばれています |
| フォルダを読み直す | 作業フォルダにファイルを足したときに押します。入力した内容とチェックは残ったまま、フォームが開き直されます |

- 作業フォルダは、Claude Code を起動したフォルダです。
- 作業フォルダの外のファイルやフォルダは、各欄の下のパス欄に書きます（参考資料は 1 行に 1 つ）。パス欄に書くと、ツリーの選択より優先されます。
- 一覧に出るのは、docx・pdf・pptx・xlsx・md・txt です。作業フォルダの 3 階層目までを調べ、隠しファイル、`.git`、`node_modules` などは出しません。1 つのフォルダに 200 件、全体で 5,000 件を超えると、一部だけ表示されます。そのときは、パス欄を使ってください。
- 依頼文と参考資料は、どちらか 1 つだけでも構いません。
- 資料は、Claude が元の場所から読みます（コピーしません）。PDF・Word・PowerPoint・Excel は、Claude の pdf・docx・pptx・xlsx スキルで読みます。PDF の図形は、ページを画像として読みます。PowerPoint と Excel は文字と図形の構造だけなので、図形が重要なときは PDF に書き出して渡してください。

### 質問への答え方

- 画面の左に、進み具合と質問の一覧が出ます。一覧の「●」は回答済み、「△」は保留、「?」は要確認、「○」は未回答です。いま答えている質問は、青い枠と札で示されます。
- 候補をクリックするか、候補の左の文字（`A`・`B`・`C`…）のキーを押して選びます。`J` で次の質問、`K` で前の質問へ移ります。
- 1 つだけ選ぶ質問は、マウスか文字キーで選ぶと、次の質問へ移ります（矢印キーで動かしただけでは移りません）。複数選べる質問は移りません。
- 緑の札「推奨」の候補が、Claude の推奨案です。理由は候補の下に出ます。
- 「コメント」を押すとコメント欄が開きます。候補を選んだときは、理由や条件の補足になります。候補を選ばずに書いたコメントは、それ自体が回答です。候補にない答えは、こちらに書いてください。
- 今決められないときは「あとで決める」、意味が分からないときは「聞き返す」を押します。聞き返しは次のラウンドで、Claude が説明か補足質問を返します。聞き返しが残っている間は、質問は終わりません。
- 選んだ候補を取り消して、コメントだけで答えるときは、「選択をクリア」を押します。

### 残るもの

承認すると、次の 1 ファイルだけが残ります。

```
<保存先>/SPEC-<テーマ>-<日付>.md
```

- 例: `SPEC-api-design-2026-10-24.md`。同じテーマを同じ日に 2 回承認すると、末尾に連番（`-2`、`-3`）が付きます。既存のファイルは上書きしません。
- 概要の「入力」に、依頼文の要約と、渡した資料の元のパスが入ります。
- 依頼文の原文、質問と回答の履歴、入力ファイルは残りません。資料はコピーしないので、元のファイルを動かすと辿れなくなります。
- 作業中のファイルは、OS の一時フォルダに置かれ、承認すると消えます。中断したものは、3 日後の次回の実行時に消えます。
- アンインストールは `/plugin` の画面から行います。このプラグインは専用の保存場所を作らないので、消えるものはありません。SPEC と、Playwright MCP の登録（ほかのツールと共有するため、不要なら自分で `claude mcp remove playwright` を実行します）は残ります。

## 設定

設定ファイルはありません。入力フォームで、毎回指定します。

- **保存先**: 初期値は作業フォルダ自身です。作業フォルダの外に置くときは、パス欄に書きます。相対パスは作業フォルダから解決されます。存在しないフォルダのときは、Claude が、新しく作ってよいかを尋ねます。保存先は、そのまま git の管理対象になります。機密を書いたときは、`.gitignore` に `SPEC-*.md` を加えてください。
- **Playwright MCP**: ブラウザを変えるときは、導入方法の手順 3 のコマンドに `--browser chrome` などを足します。

## 困ったとき

**スキルが起動しない**
- 「grill-form で〜」か「HTML で grilling」と書いて頼んでください。「grill して」だけでは、通常の `grilling` スキルが使われます。
- 入れた直後は、Claude Code を再起動してください。`/plugin` で `grill-form` が有効か確認できます。

**Playwright MCP のツール（`browser_*`）がないと言われる**
- 導入方法の手順 3 で登録し、Claude Code を再起動してください。`claude mcp list` で `playwright` を確認できます。

**すでに `playwright` を登録していて、`claude mcp add` が効かない**
1. `claude mcp get playwright` で、いまの引数とスコープを確認します。
2. `claude mcp remove playwright --scope <スコープ>` で削除します。
3. 元の引数を残したまま、`--allow-unrestricted-file-access` と `--output-dir` を付けて登録し直します。
4. Claude Code を再起動します。

**`file://` のページが開けない**
- Playwright MCP に `--allow-unrestricted-file-access` が付いているか確認してください。

**送信が検知されない**
- 「送信」を押したあと、「送信しました」と出ているか確認してください。
- 約 30 分待っても送信がないと、Claude が続行方法を聞きます。フォームの「Markdown をコピー」で、回答を貼る方法もあります。

**足したファイルが一覧に出ない**
- 一覧は、フォームを開いた時点の作業フォルダの中身です。ファイルを足したら「フォルダを読み直す」を押してください。
- 3 階層より深いフォルダ、隠しファイル、対応していない形式は出ません。パス欄にパスを書けば指定できます。

**ファイルのパスが読めない**
- 存在しないパスや、フォルダのパスは読めません。Claude から、再入力を求められます。

**SPEC が想定外の場所にできた**
- 保存先は、入力フォームの「保存先（親フォルダ）」で決まります。サブフォルダで Claude Code を起動していないか確認してください。

**一時フォルダの削除に失敗した**
- シェルのカレントフォルダが、一時セッションの中にないか確認してください。SPEC は保存済みです。残った一時フォルダは、次回の実行時に、3 日より古いものから自動で消えます。

**日本語のテーマ名が文字化けする**
- テーマ名は、ASCII の短い名前（例: `api-design`）にしてください。

**`python` コマンドが見つからない**
- `python3` に読み替えます。Claude は、自動で読み替えます。
